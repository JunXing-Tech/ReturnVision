# 14 - 多租户改造方案

---

## 〇、文档定位

退运智录（ReturnVision）原为单公司工具，飞书凭证全局单例（.env → @Value → FeishuService）。现需支持**多公司使用**，每家公司有自己的飞书应用配置，数据按公司隔离。

本文档定义多租户改造的**数据库变更、FeishuService 改造、用户隔离、用户注册机制、业务流程、接口变更**，作为后续编码的依据。

**核心原则**：
- 只做多租户改造 + 用户隔离 + 用户自助注册，不做小程序端（已取消）。
- 平滑过渡：.env 保留作默认主公司配置，现有部署不破坏。
- PC 端已有上传/SSE/确认链路不改，只改 FeishuService 凭证查询方式。
- 用户自助注册：公司管理员自助注册（飞书应用验证），普通用户用注册码注册，平台 ADMIN 不需手动创建每个用户。

---

## 一、目标与范围

### 1.1 目标

| 目标 | 说明 |
|------|------|
| 多公司飞书隔离 | 每家公司用自己的飞书应用配置写多维表格，A 公司写不进 B 公司的表 |
| 用户隔离 | 平台 ADMIN 管所有，公司 ADMIN 只管自己公司用户/记录/配置 |
| 数据隔离 | 退货记录按公司过滤，confirm 按记录所属公司查凭证写飞书 |
| 用户自助注册 | 公司管理员自助注册（带飞书应用验证），普通用户用注册码注册 |

### 1.2 不做

- 不做小程序端（已取消，见 docs/13 废弃标记）
- 不做微信登录/邀请码（PC 端用注册码 + 账号密码）
- 不做 WebSocket（PC 端已有 SSE）
- 不改 PC 端上传/SSE/确认的链路结构，只改 FeishuService 凭证查询方式

## 二、现状分析

### 2.1 现有飞书凭证链路

```
.env（FEISHU_APP_ID/SECRET/TOKEN/TABLE_ID）
  → docker-compose env_file 注入
  → application.yml（feishu.app-id: ${FEISHU_APP_ID}）
  → @Value 注入 FeishuService 构造器
  → 全局单例，所有用户共用一套凭证
```

FeishuService（`returnvision-backend/.../feishu/FeishuService.java`）：
- L31-34：四个凭证字段 `appId/appSecret/appToken/tableId`，`private final`，构造时 @Value 注入
- L44-46：`cachedToken/tokenExpireAt` 单例字段缓存 tenant_access_token
- L82：`writeRecord(Map<String,Object> recordData, String imageUrl)` —— 无租户上下文参数
- L86-89：appId 为空时跳过写入返回 null（已有降级基础）
- L168-206：`getTenantAccessToken()` 用单例字段做 token 缓存

### 2.2 写飞书调用链

- FeishuService 唯一调用方是 UploadController（全后端 grep 确认）
- `writeRecord` 唯一调用点：UploadController L737，位于 `confirmSingle(Long recordId, ReturnRecord record)`（L728-747）
- `confirmSingle` 被两个入口复用：`/api/confirm`（L497-522）、`/api/confirm/batch`（L360-398）
- 当前 confirmSingle **没有把用户上下文传给 writeRecord**

### 2.3 现有用户体系

- sys_user 表：有 `feishu_user_id`（飞书 OAuth 绑定）、`wx_openid`（v1.3 加，小程序用，保留不用）
- 角色：ADMIN / SUPERVISOR / STAFF
- AdminInitializer 创建平台 admin（admin/admin123，无公司归属）
- return_records 表：有 `created_by`（user_id，F03 操作审计加的），无 `feishu_config_id`

### 2.4 .env 现状

`.env` 文件定死了飞书应用的 `FEISHU_APP_ID/SECRET/TOKEN/TABLE_ID/BOT_WEBHOOK`，通过 docker-compose `env_file` 注入到 application.yml，再 @Value 注入 FeishuService。这是全局单例模式。

## 三、改造方案

### 3.1 数据库变更

#### 3.1.1 新增表：feishu_config（飞书多租户配置）

```sql
CREATE TABLE IF NOT EXISTS feishu_config (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    org_name        VARCHAR(100) NOT NULL COMMENT '公司/组织名称',
    app_id          VARCHAR(50)  NOT NULL COMMENT '飞书应用 ID',
    app_secret      VARCHAR(255) NOT NULL COMMENT '飞书应用密钥（AES 加密存储）',
    app_token       VARCHAR(100) NOT NULL COMMENT '多维表格 app_token（系统自动创建）',
    table_id        VARCHAR(50)  NOT NULL COMMENT '多维表格 table_id（系统自动创建）',
    bot_webhook     VARCHAR(255) COMMENT '飞书机器人 webhook（可选）',
    status          VARCHAR(20)  DEFAULT 'active' COMMENT 'active/disabled',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) COMMENT '飞书多租户配置表';
```

> app_secret 加密存储：需新增 AES 加解密工具类（项目当前无），PC 端管理界面不回显明文。app_token/table_id 由系统自动创建（见 3.6.2）。

#### 3.1.2 sys_user 加 feishu_config_id

```sql
ALTER TABLE sys_user ADD COLUMN feishu_config_id BIGINT COMMENT '所属飞书配置（NULL=平台级/未绑公司）';
CREATE INDEX idx_sys_user_feishu_config ON sys_user(feishu_config_id);
```

- NULL = 平台级（平台 ADMIN，用 .env 默认配置）
- 非空 = 绑某公司（公司 ADMIN/STAFF，用 DB feishu_config 配置）

#### 3.1.3 return_records 加 feishu_config_id

```sql
ALTER TABLE return_records ADD COLUMN feishu_config_id BIGINT COMMENT '所属飞书配置（NULL=平台级，按公司隔离用）';
CREATE INDEX idx_return_records_feishu_config ON return_records(feishu_config_id);
```

- 记录创建时写入 = 创建者 user 的 feishu_config_id
- confirm 按记录的 feishu_config_id 查凭证（不是当前用户的），防止用户换公司后旧记录写错表

#### 3.1.4 新增表：register_code（用户注册码）

```sql
CREATE TABLE IF NOT EXISTS register_code (
    id                BIGINT PRIMARY KEY AUTO_INCREMENT,
    code              VARCHAR(16) NOT NULL UNIQUE COMMENT '注册码（8位字母数字，避免 0/O/1/I）',
    feishu_config_id  BIGINT NOT NULL COMMENT '绑定的飞书配置',
    max_uses          INT DEFAULT 1 COMMENT '最大使用次数（1=一次性，N=多人共用）',
    used_count        INT DEFAULT 0 COMMENT '已使用次数',
    expires_at        DATETIME COMMENT '过期时间（NULL=永不过期）',
    status            VARCHAR(20) DEFAULT 'active' COMMENT 'active/revoked',
    created_by        BIGINT COMMENT '创建人（公司 ADMIN）',
    created_at        DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (feishu_config_id) REFERENCES feishu_config(id)
) COMMENT '用户注册码表';
```

> 公司管理员生成注册码 → 员工在 PC 端注册页输入码 → 绑公司 → 成为 STAFF。注册码可过期/限次/撤销。

### 3.2 FeishuService 改造

**现状**：全局单例 + @Value 凭证 + 单例 token 缓存。

**改造后**：

| 项 | 现状 | 改造后 |
|----|------|--------|
| 凭证来源 | .env @Value 注入 | 方法参数接收 FeishuConfig 对象 |
| 凭证字段 | private final appId 等 | 删除，改为方法参数 |
| token 缓存 | cachedToken/tokenExpireAt 单例字段 | `Map<Long/*configId*/, TokenCache>` 按 configId 隔离 |
| writeRecord 签名 | `writeRecord(data, imageUrl)` | `writeRecord(data, imageUrl, FeishuConfig config)` |
| 凭证查询 | 无 | 新增 FeishuConfigService 按 configId 查库 |

**writeRecord 改造伪代码**：
```java
public String writeRecord(Map<String, Object> recordData, String imageUrl, FeishuConfig config) {
    if (config == null || config.getAppId() == null) {
        config = getDefaultConfig();  // 兜底：用 .env 默认配置（PC 端平台 ADMIN）
    }
    String token = getTenantAccessToken(config);  // 按 configId 缓存
    // 组装字段 + 调 Bitable API（逻辑不变）
}

private String getTenantAccessToken(FeishuConfig config) {
    return tokenCache.computeIfAbsent(config.getId(), k -> fetchNewToken(config));
}
```

### 3.3 用户隔离

**角色体系**：默认两层（ADMIN + STAFF），SUPERVISOR 保留但默认不分配。

| 角色 | feishu_config_id | 职责 | 凭证来源 |
|------|------------------|------|---------|
| 平台 ADMIN | null | 管所有公司、平台运维、事后禁用恶意公司 | .env 默认配置 |
| 公司 ADMIN | 非空（绑某公司） | 管本公司用户/记录/飞书配置/生成注册码 | DB feishu_config |
| 公司 STAFF | 非空 | 录入退货、确认写飞书 | 同上 |
| SUPERVISOR（可选） | 非空 | 如果某公司需要"主管审核"环节，给某些用户此角色。默认不分配，不影响现有代码 | 同上 |

> 保留 SUPERVISOR 不改现有代码的角色体系（SecurityConfig/权限矩阵），只是默认不分配。如果某公司业务需要审核环节，再给用户 SUPERVISOR 角色。

**接口隔离规则**：

| 接口 | 平台 ADMIN（null） | 公司 ADMIN（非空） |
|------|-------------------|-------------------|
| /api/admin/users | 看所有用户 | 按 feishu_config_id 过滤只看自己公司 |
| /api/admin/feishu-config | CRUD 所有 | 只能看自己的（不能改） |
| /api/records | 看所有 | 按 feishu_config_id 过滤（STAFF 看自己 created_by，ADMIN 看本公司） |

实现方式：接口层根据当前用户 feishu_config_id 加 WHERE 条件。null 时不加过滤，非空时按 feishu_config_id 过滤。

### 3.4 .env 处理

**方案**：保留 .env 作"默认/主公司"配置，feishu_config 表存多公司配置。

**application.yml 改造**（feishu.* 保留，语义改为默认，允许空）：
```yaml
feishu:
  app-id: ${FEISHU_APP_ID:}        # 默认/主公司配置，可空（空时走 feishu_config 表）
  app-secret: ${FEISHU_APP_SECRET:}
  app-token: ${FEISHU_APP_TOKEN:}
  table-id: ${FEISHU_TABLE_ID:}
  bot-webhook: ${FEISHU_BOT_WEBHOOK:}
```

**理由**：平滑过渡（现有部署不破坏）、避免冷启动（全删 .env 后 feishu_config 表空）、PC 端兜底（平台 ADMIN 用 .env 默认）。

**.env.example 注释更新**：标注"默认/主公司配置，多租户扩展后其他公司走 feishu_config 表"。

### 3.5 confirm 凭证查询逻辑

**confirmSingle 改造**（UploadController L728-747）：

```
confirmSingle(recordId, record):
  configId = record.getFeishuConfigId()    // 按记录的公司查凭证（不是当前用户的）
  if (configId == null):
    config = getDefaultConfig()            // 平台级记录用 .env 默认
  else:
    config = feishuConfigService.getById(configId)
    if (config.status == "disabled"):
      throw BizException(2005, "飞书配置已禁用")
  feishuService.writeRecord(feishuData, imageUrl, config)
```

**防止写错表**：用户换公司后（feishu_config_id 变了），旧记录仍按记录的 feishu_config_id 写到旧公司飞书表。

### 3.6 用户注册机制

#### 3.6.1 公司管理员注册（自助 + 飞书应用验证）

**流程**：
```
PC 端注册页 → 选择"公司管理员注册"
  → 填写：用户名、密码、公司名称、飞书应用信息（app_id/app_secret）
  → 后端三步验证：
    1. 验证应用凭证：用 app_id/app_secret 调飞书 API 换 tenant_access_token
       POST https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal
       成功 → 凭证有效；失败 → 返回 2006
    2. 系统自动创建多维表格（飞书 API 支持创建 app + table + fields）
       用 tenant_access_token 创建多维表格 + 标准字段
       成功 → 拿到 app_token/table_id；失败 → 返回 2007
    3. 字段自动创建：系统维护标准字段名列表，创建表格时一并创建
  → 验证通过 → 创建 feishu_config（AES 加密 app_secret）+ sys_user（role=ADMIN, feishu_config_id）
  → 自动通过（无需平台 ADMIN 审核），平台 ADMIN 事后可禁用恶意公司
```

> **方案 B：系统自动创建标准多维表格**。公司管理员只需在飞书开放平台创建应用（拿 app_id/app_secret），注册时系统自动创建多维表格 + 所有标准字段。这样字段名一定合规，不需要手动对齐。

**标准字段列表**（系统创建表格时一并创建）：
运单号、收件人姓名、收件人电话、收件人地址、寄件人姓名、寄件人电话、寄件人地址、快递公司、托寄物、退货日期、退货原因、退货分类、图片URL、备注

#### 3.6.2 普通用户注册（注册码 + 直接创建并存）

**两种方式并存，公司管理员按需选择**：

**方式 A：注册码（批量注册）**
```
公司管理员在 PC 端生成注册码（绑自己公司 feishu_config_id）
  → 注册码可配置：有效期、最大使用次数
  → 公司管理员把注册码发给本公司仓储员工
员工在 PC 端注册页 → 选择"普通用户注册"
  → 填写：用户名、密码、注册码
  → 后端校验注册码（未过期/未用尽/未失效）→ 拿 feishu_config_id
  → 创建 sys_user（role=STAFF, feishu_config_id）
  → 注册码 used_count++
```

**方式 B：直接创建（单个添加）**
```
公司管理员在 PC 端用户管理直接创建员工账号
  → 填写：用户名、密码
  → 创建 sys_user（role=STAFF, feishu_config_id=公司管理员的）
```

> 方式 A 用于批量（新公司开户时一次性注册多个员工），方式 B 用于单个（后续新员工入职）。两者并存，公司管理员按需选择。

### 3.7 安全考虑

- **注册接口限流**：防暴力注册（同一 IP 每小时限制 N 次）
- **飞书凭证探测防护**：限制验证失败次数（同一 IP 验证飞书凭证失败 5 次后封锁 1 小时）
- **app_secret 加密**：AES 加密存储，PC 端管理界面不回显明文，接口不返回明文
- **注册码泄露**：可过期/限次/撤销，使用记录便于审计
- **密码安全**：强度校验（最少 8 位含字母+数字），BCrypt 哈希存储（现有体系已有）

## 四、业务流程

### 4.1 冷启动链路（公司管理员自助注册）

```
平台 ADMIN（AdminInitializer 创建，admin/admin123，feishu_config_id=null，用 .env 默认配置）
  → 登录 PC 端，管所有公司（事后可禁用恶意公司）

公司管理员 → PC 端注册页 → 选择"公司管理员注册"
  → 填写用户名/密码/公司名称/飞书 app_id/app_secret
  → 系统验证飞书应用 + 自动创建多维表格 + 标准字段
  → 创建 feishu_config + sys_user（role=ADMIN, feishu_config_id）
  → 自动通过，可登录 PC 端管本公司
```

### 4.2 公司管理员管理

```
公司管理员登录 PC 端
  → 生成注册码（批量注册员工）或直接创建员工账号（单个添加）
  → 查看本公司用户（按 feishu_config_id 过滤）→ /api/admin/users
  → 查看本公司退货记录（按 feishu_config_id 过滤）→ /api/records
  → 审核确认写入飞书 → /api/confirm（按记录 feishu_config_id 查凭证）
```

### 4.3 仓储员工使用

```
仓储员工登录 PC 端（账号密码，或注册码自助注册）
  → 拍照/上传图片 → /api/upload（同步）或 /api/upload/sse（SSE 流）
  → 双引擎 OCR + 交叉验证 + LLM 分析
  → 人工确认 → /api/confirm → 按记录 feishu_config_id 查凭证 → 写本公司飞书表
  → 查看自己的退货记录（按 created_by 过滤）→ /api/records
```

### 4.4 员工换公司

```
平台/公司 ADMIN 在用户管理改 feishu_config_id
  → 旧记录 feishu_config_id 不变（创建时写入），仍写到旧公司飞书表
  → 新记录按新 feishu_config_id 写到新公司飞书表
```

### 4.5 平台 ADMIN 管理

```
平台 ADMIN（feishu_config_id=null）登录 PC 端
  → 查看所有公司 feishu_config → /api/admin/feishu-config
  → 禁用恶意公司（feishu_config.status=disabled）→ 该公司用户不能录入（2005 错误码）
  → 查看所有用户/记录
  → 确认记录时按记录的 feishu_config_id 查凭证，null 用 .env 默认
```

## 七、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| token 缓存跨租户串号 | A 公司写到 B 公司飞书表 | token 缓存改 `Map<configId, TokenCache>` 按 configId 隔离 |
| PC 端现有写飞书破坏 | 单租户场景写飞书失效 | .env 保留作默认 + feishu_config 预置一条主公司行兜底；回归测试 |
| app_secret 泄露 | 密钥泄露 | AES 加密存储 + 管理界面不回显 + 接口不返回明文 |
| 飞书凭证被恶意探测 | 暴力枚举别人飞书凭证 | 限制验证失败次数（5 次后封锁 1 小时）+ 注册接口限流 |
| 注册码泄露 | 陌生人注册进公司 | 注册码可过期/限次/撤销 + 使用记录审计 |
| 用户换公司后旧记录写错表 | 数据写到错误公司 | confirm 按记录的 feishu_config_id 查凭证（不是当前用户的） |
| 接口过滤遗漏 | 公司 ADMIN 看到其他公司数据 | 接口层统一加 feishu_config_id 过滤 + 单元测试覆盖 |
| AES 加解密工具缺失 | app_secret 无法加密 | 新增 AES 工具类（项目当前无） |
| 飞书多维表格创建失败 | 公司管理员注册失败 | 验证飞书应用权限足够 + 明确错误提示（2007）+ 可重试 |

## 八、业务流程改进清单

> 核心退货录入链路通畅，但异常分支/降级/状态同步有改进空间。11 条按优先级分层（第 9 条首次改密已排除）。

### 8.1 必做（核心链路异常分支）

| # | 改进点 | 现状 | 方案 |
|---|--------|------|------|
| 1 | 飞书写入失败处理 | confirm 后写飞书失败，记录状态不明确 | 失败 → status=failed + 错误信息 → 列表标红 → 重试入口 → 多次失败标记"需人工介入" |
| 2 | OCR 全失败降级 | 双引擎全挂时无手动入口 | OCR 全失败 → 手动录入表单 → ocr_engine=manual → 仍可确认写飞书 |
| 3 | LLM 分析失败降级 | DeepSeek 失败时流程是否阻塞 | LLM 失败 → 退货原因/分类留空 → 用户手动填 → 不阻塞确认 |
| 4 | 图片质量预检 | 有 EXIF 矫正+压缩，无清晰度检测 | 上传前检测模糊度/尺寸/亮度 → 模糊或过暗提示重拍 |

### 8.2 建议（多租户状态同步）

| # | 改进点 | 现状 | 方案 |
|---|--------|------|------|
| 5 | 飞书配置变更 token 缓存清除 | 改配置后旧 token 可能残留 | feishu_config 更新时清除 tokenCache.get(configId)，下次重新获取 |
| 6 | 公司禁用后用户处理 | disabled 后已签发 JWT 是否有效 | 不主动踢人（JWT 无状态），但请求时查 DB 确认 feishu_config.status → disabled 拒绝（2005）→ 前端跳登录提示 |
| 7 | 现有数据迁移 | return_records 无 feishu_config_id | 迁移脚本设为 .env 默认公司的 config_id（预置一条主公司行） |

### 8.3 可选（用户体系与体验）

| # | 改进点 | 现状 | 方案 |
|---|--------|------|------|
| 8 | 密码找回 | sys_user 无邮箱/手机字段 | sys_user 加 email/phone → 忘记密码 → 验证码重置；或简化为管理员重置 |
| 10 | 数据导出 | 记录列表无导出 | /api/records/export 导出 Excel/CSV（按 feishu_config_id 过滤） |
| 11 | 重复运单上传提示 | WaybillValidator 有去重但是否提前提示 | upload 时检测重复 → SSE 推送"该运单已录入过" → 用户选择继续或取消 |
| 12 | 飞书表格字段变更校验 | 注册时自动建字段，后续手动改会写失败 | writeRecord 失败时检查字段名 → 不匹配提示"飞书表格字段已变更，联系管理员重新校验" |

> 改进点 1-4 在多租户改造步骤 5-9 之间穿插做（confirmSingle 改造时顺带做第 1 条，OCR/LLM 降级在 upload 链路改造时做）。5-7 在多租户改造步骤 4-6 做。8/10/11/12 作为后续迭代。
